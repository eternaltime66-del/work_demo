# 接口与前端

## 1. 通用约定

- 玩家接口前缀：`/api/**`。
- 后台接口前缀：`/back/**`。
- 绝大多数请求使用 POST。
- 普通参数使用表单编码；数组/对象替换接口可能使用 JSON。
- 登录后通过 `token` Header 鉴权。
- 响应统一封装为 `WxResult<T>`。

## 4. 工具与公共接口

`/api/unit`：

- `/send/code`：发送验证码；
- `/upload`：文件上传；
- `/config/list`：读取公开配置列表。

根路径 `/` 返回文本响应，用于基本服务探活。

## 5. 玩家前端页面

| 页面 | 职责 |
|---|---|
| `app/login.html` | 邮箱密码/验证码登录 |
| `app/register.html` | 邮箱注册 |
| `app/change-password.html` | 修改或重设密码 |
| `app/index.html` | 首页、角色、备战、仓库、合成、关卡入口 |
| `app/battle.html` | 获取战斗结果并播放事件 |
| `app/monery.html` | 钱包/积分相关页面 |

`index.html` 与 `battle.html` 体积较大，Vue 状态、模板和业务行为集中在单文件中。新增大功能时建议拆为模块或组件，否则回归风险会持续升高。

## 6. API 客户端

`app/js/api.js` 提供：

- token 保存、读取与清理；
- 表单 POST；
- JSON POST；
- 统一成功检查；
- 账号、用户、角色、关卡、备战、合成、战斗等方法。

当前 `request()` 无统一超时、取消、HTTP 非 2xx 处理和 token 失效跳转；网络异常由调用页面自行捕获。

## 7. 战斗页面数据流

```text
index.html 选择关卡
→ 调用预览/战斗接口
→ 服务端一次性演算
→ 返回 BattleResultVo + events
→ battle.html 按 AV/事件顺序播放
→ 展示胜负、掉落和奖励
→ 返回主页后刷新进度/库存
```

## 8. 后台页面

`admin/index.html` 集成全部配置编辑器。优点是部署简单；缺点是单文件超大、跨模块状态耦合、难以测试。技能公式画布、主动/被动/Buff 编辑是最复杂区域，任何枚举或字段变更都要同步：Java 实体、Controller、后台选项与描述展示。

## 9. 接口变更清单

新增字段或枚举时至少核对：

1. 数据库字段与实体；
2. Mapper/MyBatis 转换；
3. Service 默认值和校验；
4. 后台表单和 options；
5. 玩家详情 VO；
6. `api.js` 参数；
7. 战斗装载与事件序列化；
8. 本目录文档和回归测试。
