# v5 整改实施记录

> 本文记录已实际落入 v5 源码并通过自动化测试的修改。未列为“完成”的路线图事项仍不能视为已解决。

## 1. 已完成：资产安全止血

### 玩家自报掉落入口

- 删除 `/api/monster/drop/settle` Controller 方法；
- 删除前端 `monsterDropSettle()`；
- 正式掉落只从服务端 `BattleService` 的胜利结算路径入仓；
- `/roll` 仍是纯试算，不写资产。

### 硬编码超级登录

- 删除 `/api/user/super/token`；
- 删除硬编码 `9527`；
- 删除 `MemberService.superToken(uid)`，避免内部误用重新暴露。

### 无尽塔重置

- `RUNNING` 且有当前层时，再次 enter 直接恢复当前状态；
- 不再覆盖到第一层和清空继承生命；
- enter 与塔战斗使用同一玩家锁。

## 2. 已完成：分布式锁安全

- Redis 锁值由固定 `1` 改为每次请求 UUID owner token；
- 解锁使用 Lua compare-and-delete，旧请求不能删除新持有者的锁；
- 获取、业务执行和释放合并到一个 `@Around + finally`；
- 锁切面显式高于事务切面，保证事务提交后再释放锁；
- 注解新增 `leaseSeconds`；战斗锁租期为 300 秒；
- 等待中断时恢复线程中断状态；
- 多字段锁 key 使用稳定的插入顺序；
- 主线战斗、塔战斗、塔进入、合成和全部备战资产操作统一使用不绑定方法名的 uid 锁。

说明：数据库唯一约束、奖励账本和跨实例原子 SQL 仍建议实施。Redis 锁是第一层保护，不替代数据库约束。

## 3. 已完成：战斗正确性

### 死亡幂等

- V2 输出、旧技能效果和旧被动效果均在每段前重新检查目标存活；
- 统一伤害入口拒绝死亡目标；
- 击杀只在 `hpBefore > 0 && hpAfter == 0` 时成立；
- 死亡、击杀、击杀充能和击杀被动不会因后续段重复触发。

### 有效伤害

- 新口径：`effectiveDamage = hpBefore - hpAfter`；
- 伤害统计、HIT 事件、日志、吸血、伤害后被动和旧 cast bag 使用实际掉血；
- 对 10 HP 目标造成理论 100 伤害，只统计和吸血 10。

### 实际目标

- 删除施法前为 CAST 事件预解析目标的逻辑；
- V2 属性/效果/Buff 与旧 SkillEffect 执行时记录实际目标；
- CAST.targets、释放后和受到技能后被动使用实际执行目标；
- 随机目标不会在“展示”和“结算”阶段分别随机。

### 攻速

- V2 `ATK_SPEED` 修改后立即重算行动阈值；
- 重算按旧行动条完成比例映射到新阈值；
- Buff 撤回时同样恢复行动阈值和进度比例。

### Buff 到期轴

- 同一 AV 先执行应发生的脉冲，再清理到期 Buff；
- 持续 100 AV、间隔 100 AV 的 Buff 会在 100 AV 触发一次后结束。

## 4. 已完成：输入与接口安全

### 掉落配置

- 后台保存统一走 `MonsterDropService.savePrepared()`；
- 概率限制 0~100，并以小数精度抽取，不再 `intValue()` 截断；
- 最小数量必须大于 0；
- 最大数量不得小于最小数量；
- 单次配置数量增加保护上限；
- 补齐排序、启用和数量默认值。

### 上传

- `/api/unit/upload` 改为仅 ADMIN；
- 只允许 POST；
- 最大 5 MB；
- 扩展名和 MIME 双重检查；
- 服务端随机文件名；
- 删除未正确推进读取位置的原始输入流分支。

### 验证码

- 恢复 Redis 原子计数限频；
- 同一账号/类型每天最多 10 次。

### CORS 与上传目录

- CORS 默认从任意来源收紧为本机开发来源；
- 生产环境通过 `APP_CORS_ALLOWED_ORIGIN_PATTERNS` 明确配置允许域名；
- 上传写入与 `/uploads/**` 静态映射共用同一组配置；
- Windows/Linux 根目录分别由 `APP_UPLOAD_ROOT_WINDOWS`、`APP_UPLOAD_ROOT_LINUX` 覆盖。

## 7. 行为兼容提醒

- 调用 `/api/monster/drop/settle` 或 `/api/user/super/token` 的旧客户端会收到 404；这是主动安全收口。
- 上传接口现在必须使用管理员 token，并且只接受标准 JPEG/PNG MIME。
- 掉落配置中 `minQty=0` 或 `maxQty<minQty` 将拒绝保存，需要先清理旧配置。
- 过量伤害、吸血和伤害阈值数值会比旧版本更合理但可能变小，需要重新检查依赖旧漏洞的 Build。
- 持续时间等于脉冲间隔的 Buff 现在会按设计触发一次，可能改变旧战斗结果。

## 8. 战斗触发器与阶段结算升级

- 战斗事件被动新增 `PASSIVE_TRIGGER` 结构化事件，记录被动、触发事件、关联目标和伤害；
- 被动输出使用独立执行上下文，不再继承外层主动技能信息；
- 被动命中的额外目标不再污染主动技能 `CAST.targets`；
- 增加触发链活动集合和 64 层硬上限，错误配置形成循环时安全跳过；
- 胜负判断统一放到原子结算阶段之后：充能技、Buff 脉冲、延时开战被动和每次行动后都会立即判断；
- Buff 脉冲击杀最后目标后，不再允许其他单位多行动一次；
- 同一结算点双方全灭明确判定为 `DRAW`；
- 战斗演算、掉落、首通奖励、体力及塔进度仍在玩家级 Redis 锁和同一数据库事务内完成。

统一 VA 与全主动技能充能模型详见 `09-统一VA充能与战斗触发模型.md`。
