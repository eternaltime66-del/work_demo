# 已知问题与能力边界

> 本文用于开发排序，不代表已完成修复。凡涉及经济资产或并发的问题，修复前应先补回归测试。

逐项实施步骤、数据迁移和验收标准见 [07-分级整改与优化路线图.md](07-分级整改与优化路线图.md)。

## 1. 风险分级

- **P0**：可直接重复生成资产、破坏战斗核心结算或形成无限资源闭环。
- **P1**：高概率数据不一致、规则明显失效或可绕过限制。
- **P2**：统计、展示、边界和维护性问题。
- **待确认**：代码行为明确，但是否属于 Bug 取决于产品设计。

## 2. P0：优先处理

### 2.1 客户端自报怪物直接结算掉落

入口：`A11MonsterDropController /api/monster/drop/settle`。

风险：客户端提交怪物 ID，服务端按列表抽奖并写仓库，未与一次服务端战斗结果、不可重放结算令牌或已击杀集合绑定。可能伪造高价值怪物、重复 ID、重复调用。

建议：删除玩家直接结算入口，掉落只允许在 `BattleService` 的服务端胜利事务中结算；若必须分步，使用一次性、签名、绑定 uid/战斗/击杀集合/过期时间的结算票据并原子消费。

### 2.2 多段技能可能重复攻击尸体

风险：目标存活检查位于段循环外时，第一段击杀后后续段仍可能继续结算，重复产生死亡/击杀事件、击杀充能、被动和吸血。

建议：每段开始和伤害应用入口都检查存活；死亡事件只允许由 `hp > 0 → hp == 0` 的状态跃迁产生。

### 2.3 无尽塔可重复重置刷资源

`TowerRunService.enter()` 可重新定位首层，当前未看到门票、体力、冷却或重置次数，塔战胜利会发正常怪物掉落。

建议：明确塔设计。如果不可重复刷，限制 RUNNING 状态重新 enter，增加重置规则和奖励领取记录；如果允许重开，区分首通奖励与可重复掉落并设置成本/次数。

### 2.4 战斗并发导致重复奖励

主线和塔战斗有事务但没有同 uid 的统一互斥。两个请求可能同时读取旧体力、次数、首通或塔层状态，并分别发奖励。

建议：建立玩家资产域统一锁；数据库增加唯一约束、条件更新或行锁；奖励记录使用幂等业务 ID。

## 3. P1：规则与一致性

### 3.1 Redis 锁所有权不安全

当前锁值固定，释放直接删除。如果 A 的锁过期后 B 获得新锁，A 完成时可能删除 B 的锁。默认 `bindMethod=true` 还会让同一玩家的不同资产方法使用不同 key。

建议：随机 owner token + Lua compare-and-delete；资产操作统一 `player:{uid}` 或更明确的域锁；长事务支持续期或选择合理 TTL。

### 3.2 体力、每日次数和首通存在 lost update

典型“读取 → Java 修改 → updateById”无法抵御并发。需结合玩家锁和数据库条件更新，例如 `UPDATE ... WHERE stamina >= cost`。

### 3.3 getOrCreate 并发重复

玩家体力、关卡进度、章节进度、仓库、塔运行等都有先查后插模式。必须由 `(uid, business_key)` 唯一索引兜底，并正确处理重复键后重查。

### 3.4 V2 攻速修改可能不改变行动间隔

V2 属性输出修改 `atkSpeedAdd`，但若未同步重算 `action`，单位真实出手频率不变。

建议：所有攻速变更统一通过一个重新计算入口，并决定是否保持当前行动条完成比例。

### 3.5 随机/动态目标重复解析

CAST 展示/受技能后事件与 V2 输出可能分别解析目标。随机目标可出现动画 A、实际伤害 B；前一输出改变战局后，后续动态目标也可能变化。

建议：明确技能级锁定还是输出级动态选择；事件必须使用实际执行结果目标集合。

### 3.6 V2 与旧锚点统计断层

旧锚点依赖 cast bag 和旧效果路径；V2 输出未必填充同一上下文，导致充能技能伤害锚点不触发或读取 0。

建议：统一伤害上下文和技能执行报告，旧/新输出都写入相同事件总线。

### 3.7 多段过量伤害扩大吸血

伤害统计与吸血可能采用理论伤害，不以目标实际失血封顶。对残血目标的大伤害会产生超额吸血和阈值统计。

建议：区分 `calculatedDamage` 与 `effectiveDamage`，明确吸血、统计、触发器各自使用哪一项。

### 3.8 Buff 到期与脉冲同 AV 顺序

当前可能先移除到期 Buff 再处理脉冲，因此持续 100 AV、间隔 100 AV 的 Buff 可能一次也不触发。

建议：明确区间语义 `[start,end)` 或 `[start,end]`，用测试固定临界点行为。

## 4. P2：统计、展示与工程质量

### 4.1 战斗统计口径不统一

- 伤害可能含过量，治疗通常按实际量；
- V2 治疗进入统计，旧治疗、吸血等未必进入；
- `ACTIVE_COUNT` 是伤害段数而非施法次数；
- `RECEIVE` 更接近受主动技能伤害段；
- 致死伤害的统计、充能和“受到伤害后”被动口径不同。

建议建立统一 `BattleEvent/CombatRecord`，所有系统基于同一事实事件派生统计。

### 4.2 存活单位聚合导致历史值消失

`ALL_ALLY/ALL_ENEMY` 只聚合存活单位。成员死亡后其历史累计伤害从团队总量消失，与脉冲阈值组合可能重复跨档。

### 4.3 掉落预览不是综合概率

同物品来自多个怪物时，预览没有计算至少掉落一次的联合概率。UI 应标注为“单来源最高概率/配置摘要”，或按怪物数量和独立事件计算真实范围。

### 4.4 掉率与数量边界

需复核 BigDecimal 到整数的转换精度、min/max 交换、负数归零和 `0~N` 形成隐性二次不掉落等行为，并在后台保存时拒绝模糊配置。

### 4.5 时间单位展示不闭合

引擎的攻速公式与前端 `50 AV = 1 秒` 展示导致攻速 1 等于约 0.5 次/秒。需要选定唯一时间单位并全局统一。

### 4.6 公式错误静默返回 0

非法 JSON、错误枚举、除零等多处返回 0，配置错误难发现。建议后台保存时严格验证，运行时记录技能 ID、输出 ID 和公式错误。

### 4.7 自动化测试不足

目前只有上下文启动测试。战斗和经济系统缺少最小回归网，任何调整都有高回归风险。

## 5. 待确认设计

### 5.1 装备是否全队共享

当前装备平坦属性、武器普攻、装备主动技能和装备被动会被装载到每个上阵角色。若装备定义为玩家全队装备，这是功能；若是主角个人装备，则是严重范围错误。

### 5.2 首通前挑战是否永久免费

当前逻辑是未 cleared 时每次成本为 0。需要确认设计是“第一次挑战免费”还是“首通前重试免费”。

### 5.3 怪物技能优先级

怪物没有独立 AI，使用统一自动释放规则。若需要血线决策、权重、冷却或随机策略，需要新增 AI 层。

### 5.4 致死伤害事件

死者通常不会再触发普通“受到伤害后/受到技能后”，只触发被击杀事件。需确认玩法语义。

## 6. 已预留但未完整实现

- 暴击率和暴击伤害完整结算；当前事件中的 crit 不构成完整暴击系统。
- 装备随机词条、品质随机生成、强化和洗练。
- 玩家自定义装备主动/被动槽；当前主要使用管理员配置的默认绑定。
- 召唤物在战斗中的动态生成及继承召唤者属性闭环。
- 护盾、硬控、驱散等独立效果类型；可通过现有 Buff/属性组合模拟一部分，但不是原生完整系统。
- 真正的怪物 AI。
- 体力自然恢复完整闭环。

## 7. 建议测试矩阵

### 经济与并发

- 同 uid 并发主线战斗 2/10/100 请求；
- 并发首通、章节首通；
- 并发塔层战斗和重复 enter；
- 仓库只剩一个槽时并发掉落/合成；
- 同一结算票据重复提交；
- getOrCreate 唯一约束冲突。

### 战斗

- 多段第一段击杀；
- 过量伤害吸血；
- 随机目标的 CAST 与 HIT 一致性；
- Buff 在到期 AV 的最后一次脉冲；
- 攻速 Buff 前后行动间隔；
- 角色死亡前后团队累计阈值；
- V2 与旧技能路径的事件一致性；
- 同 AV：充能技、脉冲、普攻先后顺序。

### 资产

- 仓库堆叠上限和跨槽消耗；
- 合成失败完整回滚；
- 穿戴类型/所有权/位置绕过；
- 掉落重复怪物 ID、禁用怪物、超长列表；
- 首通奖励仓库满时的事务行为。

## 8. 推荐修复顺序

1. 关闭或重构客户端掉落 settle。
2. 修复尸体多段重复击杀。
3. 为主线、塔和资产变更建立统一幂等与并发保护。
4. 限制塔重置和奖励循环。
5. 升级 Redis 锁所有权语义。
6. 补 P0/P1 自动化测试。
7. 统一目标解析、V2/旧事件和伤害统计模型。
8. 修复攻速、Buff 边界和时间单位。
9. 再扩展暴击、召唤、装备自定义等新能力。
