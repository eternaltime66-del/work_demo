# 项目总览与架构

## 1. 技术栈

### 后端

- Java 17。
- Spring Boot 3.5.7。
- Spring MVC：HTTP API 与静态资源服务。
- Spring AOP：参数检查、请求头鉴权、Redis 锁、日志。
- MyBatis-Plus 3.5.5：实体映射、CRUD、逻辑删除和分页。
- MySQL 8.x 驱动与 Druid 数据源。
- Spring Data Redis（Lettuce）。
- Fastjson2、Hutool、Guava、Lombok。
- Web3j、bitcoinj、BouncyCastle 和 OkHttp 仍在依赖中；当前核心游戏闭环主要依赖账户积分钱包，不以链上交易作为战斗前提。

### 前端

- Spring Boot `static` 目录直接托管。
- Vue 3 production runtime 以脚本文件直接加载。
- 原生 `fetch` 调用后端，主要使用 `application/x-www-form-urlencoded`，批量结构使用 JSON。
- 页面样式按基础、布局、首页、备战、仓库、合成和战斗拆分。

## 2. 启动与配置

入口类：`org.wx.core.Web3Application`。

启用了：

- `@EnableScheduling`；
- `@EnableAsync`；
- Spring Boot 自动配置。

配置文件：

| 文件 | 用途 |
|---|---|
| `application.yml` | 默认端口、数据源、Redis、MyBatis-Plus、线程池 |
| `application-dev.yml` | DevTools、LiveReload、静态资源缓存策略 |
| `application-remote.yml` | 远程数据源覆盖；当前未纳入 Git，禁止提交凭据 |
| `run-dev.cmd` | Windows 开发启动入口 |

默认可通过 Maven Wrapper 启动。运行前必须提供可访问的 MySQL 和 Redis，并确认所选 profile 的连接信息。

## 4. 后端分层

常规调用链：

```text
HTTP 请求
  → Controller
  → AOP：参数、token/角色、请求日志
  → Service：规则、事务、组合查询
  → Mapper/MyBatis-Plus
  → MySQL
  → WxResult<T>
```

Controller 负责参数和响应包装；复杂业务集中在 Service；实体既承担表映射，也包含部分展示辅助字段；VO 用于组合页面数据和战斗结果。

## 5. 通用基础设施

### 响应格式

Controller 统一返回 `WxResult<T>`。前端 `GameApi.ensureSuccess()` 以 `success === false` 判断失败并使用 `msg` 展示错误。

### 身份与鉴权

- 玩家登录后把 token 保存到 `localStorage`。
- 前端每次 API 请求在 `token` Header 中发送。
- `@NeedHeader(roles = MemberRole.USER)` 保护玩家接口。
- 后台接口使用管理员角色要求。
- `Wx.memberId()` 从请求上下文取得当前用户 ID，业务接口不应相信客户端自报 uid。

### 参数校验

`@ParamCheck` 由 AOP 检查必填参数。复杂的枚举、数量、所有权和状态仍由 Service 验证。

### 事务

资产变更服务使用 Spring `@Transactional`。事务能保证单次请求失败回滚，但不自动解决两个并发事务之间的重复领取或丢失更新。

### Redis 锁

`@RedisLock` 通过 `SETNX + TTL` 获取锁。当前实现需要注意：锁值不是持有者 token，释放使用直接删除；默认 key 绑定类名和方法名，因此跨方法的同一资产操作不天然互斥。详见问题文档。

### 逻辑删除与审计字段

实体继承 `WxBaseEntity`，MyBatis-Plus 配置使用统一 ID 策略和逻辑删除字段。具体表结构应以目标数据库 DDL 为准；项目根目录 SQL 体积较大且不属于源码文档的唯一事实来源。

## 6. Web 与静态资源

- CORS 当前允许任意来源模式、全部常用方法和 Header，不使用 Cookie 凭证。
- `/uploads/**` 映射到操作系统文件目录。
- `/art/**` 兼容映射到 `static/app/art/`。
- 玩家入口通常为 `/app/index.html`，战斗页为 `/app/battle.html`。
- 后台入口为 `/admin/index.html`。

## 7. 前端结构

### 玩家端

`app/index.html` 是主要单页，覆盖首页、备战、仓库、合成和出击入口；`battle.html` 独立负责战斗事件播放。登录、注册和修改密码使用独立页面。

核心脚本：

| 文件 | 作用 |
|---|---|
| `js/config.js` | API 根地址、token key 等运行配置 |
| `js/api.js` | 玩家 API 封装 |
| `js/art.js` | 美术资源填充/映射 |
| `js/composables/useDragMove.js` | 拖拽交互 |
| `js/dev-live.js` | 开发热更新辅助 |

### 后台

`admin/index.html` 是大型单文件后台页面，包含会员、角色、技能、Buff、物品、配方、怪物、掉落、关卡等管理界面。它直接调用 `/back/**` 接口。

## 8. 主要设计特征

- 服务端权威战斗：前端不计算最终胜负，只播放事件。
- 配置驱动技能：主动技能、输出、充能、被动、条件和 Buff 分表配置。
- 角色模板复制：玩家获得角色时把模板数据复制到玩家角色实例，模板后改不会自动同步旧角色。
- 三层物品位置：仓库、战斗背包、穿戴槽。
- 关卡树：TYPE → CHAPTER → LEVEL。
- 主线与无尽塔共用战斗引擎，但进度、消耗和生命继承规则不同。
