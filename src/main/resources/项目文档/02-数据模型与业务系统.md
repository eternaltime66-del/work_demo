# 数据模型与业务系统

## 1. 数据域总览

| 数据域 | 核心表/实体 | 职责 |
|---|---|---|
| 账号 | `app_member` | 用户身份、登录凭据、角色 |
| 钱包 | `app_point_wallet`、`app_point_pay_order` | 积分钱包和订单流水 |
| 角色模板 | `app_role_base_stat` | 可发放角色的基础模板 |
| 玩家角色 | `app_player_role`、`app_player_role_skill` | 玩家持有角色及角色技能 |
| 布阵 | `app_player_layout` | 上阵角色和网格位置 |
| 物品 | `app_item` + 各部位扩展表 | 物品公共信息及类型属性 |
| 仓库 | `app_warehouse`、`app_warehouse_item` | 永久库存和槽位 |
| 战斗背包 | `app_battle_bag` | 备战携带物品 |
| 装备 | `app_player_equip` | 玩家当前各部位穿戴 |
| 配方 | `app_recipe`、`app_recipe_material` | 合成产出与材料 |
| 怪物 | `app_monster`、`app_monster_drop` | 怪物模板及掉落 |
| 关卡 | `app_stage`、`app_stage_level_monster` | 关卡树与怪物布置 |
| 进度 | `app_player_stage_level`、`app_player_stage_chapter` | 通关、次数、首通 |
| 体力/塔 | `app_player_stamina`、`app_player_tower_run` | 消耗资源和塔运行状态 |
| 技能 | `app_active_skill`、`app_skill_charge`、`app_skill_output` | 主动技能配置 |
| 被动 | `app_passive_skill`、条件/效果表 | 被动规则与旧兼容效果 |
| Buff | `app_buff_def` | 标准 Buff 定义 |

## 2. 账号与玩家初始化

### 注册与登录

支持：

- 邮箱 + 验证码注册；
- 邮箱 + 密码登录；
- 邮箱 + 验证码登录；
- 登录后修改密码；
- 通过验证码设置密码。

登录成功返回 token，随后所有玩家接口从 token 解析当前 `memberId`。

### 默认数据

玩家首次进入时会补齐默认角色。`PlayerRoleService` 提供：

- `grantDefaultRoles()`：发放默认角色；
- `ensureMainRole()`：确保主角存在；
- `ensureAllRolesNormalSkill()`：确保角色有普通攻击技能。

管理后台可重置玩家游戏数据、赠送角色/资产和体力。

## 3. 角色系统

### 角色模板与实例

`RoleBaseStat` 是发放模板，`PlayerRole` 是玩家实例。发放时复制基础/额外攻血防、行动与攻速、各种伤害倍率、元素加成和抗性等字段。

重要行为：模板不是实时引用。后台修改模板不会自动更新已经发给玩家的实例。

### 角色分类

- `HERO`：主角；
- `PARTNER`：伙伴；
- `SUMMON`：召唤物。

怪物侧另有 `MONSTER` 与 `SUMMON` 分类。召唤继承字段存在于数据模型，但当前完整战斗召唤链并未落地，属于预留能力。

### 角色技能

`PlayerRoleSkill` 绑定玩家角色与主动技能，并保存排序。角色战斗技能装载以该排序为依据；`ActiveSkill.sort` 不是玩家角色战斗优先级的唯一来源。

## 4. 布阵系统

`PlayerLayout` 保存玩家角色、位置和排序。战场使用 6×6 网格语义，角色/怪物有宽高，占位不能越界或重叠。

布阵保存前应满足：

- 角色属于当前玩家；
- 位置合法；
- 同一角色不重复；
- 占地不重叠；
- 上阵数量及主角约束符合 Service 规则。

战斗加载时按布阵生成己方 `BattleRuntimeUnit`；关卡怪物布置生成敌方单位。

## 5. 物品系统

### 物品类型

- `MATERIAL` 材料；
- `WEAPON` 武器；
- `ARMOR` 护甲；
- `GLOVES` 护手；
- `HELMET` 头盔；
- `ACCESSORY` 饰品；
- `LEGS` 护腿。

`Item` 保存公共字段，各类型扩展表保存攻血防、攻速等部位属性。物品详情服务把公共数据、扩展数据、默认主动技能和默认被动组合为前端详情。

### 默认技能与被动

- `ItemDefaultSkill`：装备默认主动技能；
- `ItemDefaultPassive`：装备默认被动。

这些由管理员配置，装备进入战斗时解析。物品上虽然预留玩家可编辑技能/被动槽位数量，但当前没有完整的玩家洗练、插槽保存和战斗装载链。

## 6. 仓库、战斗背包与装备

### 仓库

仓库是持久资产主库存：

- `Warehouse` 保存玩家仓库容量；
- `WarehouseItem` 保存槽位、物品和数量；
- 材料可按物品规则堆叠；
- 装备通常按实例/单件处理；
- 新增物品时优先合并可堆叠槽，再使用空槽；
- 消耗时跨槽扣减，数量归零后删除槽位记录。

### 战斗背包

`BattleBag` 是备战携带层。`PrepService` 支持仓库与战斗背包之间的单项拖拽和批量移动。

### 装备

穿戴槽：武器、护甲、护手、头盔、饰品、护腿。装备操作需要验证物品位置、类型和槽位匹配。

当前代码将玩家装备汇总成一份 `EquipBonusVo`，在构建每个上阵角色时重复加入，因此装备三围实际对全队生效。装备技能和装备被动也会装载给每个上阵角色；这是明确代码行为，但是否符合“全队装备”设计需要产品确认。

## 7. 备战聚合

`PrepService.getSummary(uid)` 一次返回：

- 玩家角色及展示属性；
- 角色技能槽；
- 当前穿戴槽；
- 战斗背包；
- 仓库详情。

主要操作：

- 仓库 → 战斗背包；
- 战斗背包 → 仓库；
- 通用拖拽转移；
- 穿戴；
- 卸下；
- 批量移动。

## 8. 配方与合成

`Recipe` 定义产出物品、产出数量、启用状态和排序；`RecipeMaterial` 定义每种材料数量。

玩家合成流程：

```text
读取启用配方
  → 汇总仓库材料数量
  → 校验所有材料足够
  → 校验产物和数量合法
  → 事务内扣除材料
  → 事务内向仓库加入产物
  → 返回新库存/配方展示数据
```

若仓库容量不足或任一步骤抛出运行时异常，事务应回滚整个合成。

## 9. 怪物与掉落

### 怪物

怪物包含：

- 基础攻血防与行动字段；
- 高级伤害比例和元素属性；
- 普攻、小技能、大招关联；
- 稀有度和网格尺寸；
- 分类与启用状态。

怪物稀有度默认占地：普通 1×1、稀有 1×2、史诗 2×2、Boss 2×4，特殊类型可编辑。

### 掉落

`MonsterDrop` 关联怪物和物品，配置掉率、最小数量、最大数量。战斗胜利后根据实际击杀怪物来源 ID 抽取并发到仓库。

掉落预览会聚合关卡内怪物的掉落来源，但当前展示更接近配置摘要，并非严格计算“至少掉落一次”的综合概率。

独立的 `/api/monster/drop/settle` 玩家接口允许提交怪物列表直接结算，当前缺少与真实战斗结果绑定的凭证，属于高优先级资产风险。

## 10. 关卡系统

### 树结构

```text
TYPE（模式根，如 MAIN/TOWER）
  └── CHAPTER（章节）
      └── LEVEL（可战斗小关）
```

关卡保存启用状态、排序、体力成本、每日次数等字段。`StageLevelMonster` 保存怪物在 6×6 网格的位置和占地。

### 解锁

主线按排序和前置通关推进；章节是否开放取决于上一个章节/关卡进度。Service 统一生成玩家可见的进度树和关卡预览。

## 11. 主线流程

```text
请求关卡预览
  → 检查关卡存在、启用、属于主线
  → 检查解锁
  → 检查每日次数
  → 计算体力成本
  → 服务端演算战斗
  → 记录本次尝试
  → 胜利：更新进度、抽怪物掉落、发小关/章节首通奖励
```

当前体力规则：尚未通关时 `fightStaminaCost()` 返回 0；通关后重复挑战才按配置扣体力。因此实际语义是“首通前所有尝试免费”，并非仅第一次挑战免费。

失败/平局仍可计入每日尝试，但不发胜利掉落和首通奖励。

## 12. 首通奖励

`StageFirstReward` 可以挂在小关或章节。首次胜利：

- 更新小关 cleared；
- 若小关首通奖励未领取则发仓库；
- 若章节所有关卡完成，则发章节首通奖励；
- 标记领取状态。

整个单请求受事务保护，但当前缺少同玩家战斗级互斥，并发请求可能同时看到“未领取”。

## 13. 体力

`PlayerStaminaService` 提供创建、扣减和增加。当前源码能看到体力存储和管理赠送，但未形成明确的自然恢复定时任务闭环。

## 14. 无尽塔

`PlayerTowerRun` 保存：

- 当前状态：`RUNNING/CLEARED/DEAD`；
- 当前关卡；
- 己方剩余生命 JSON。

进入塔会定位到塔模式第一关；连续胜利推进下一关，并继承己方剩余生命；失败标记为 `DEAD`；到末层后标记 `CLEARED`。

当前 `enter()` 可重新初始化运行，且未看到门票、体力、冷却或每日重置成本；塔层胜利仍发怪物掉落。这使重复进入和并发挑战具有经济风险。

## 15. 后台内容管理

后台已覆盖：

- 会员与玩家数据；
- 角色模板与玩家角色；
- 系统参数；
- 主动技能、充能、输出、旧效果；
- 被动技能、条件、效果；
- Buff；
- 怪物与掉落；
- 物品各类型扩展、默认技能和默认被动；
- 配方与材料；
- 关卡树、首通奖励、怪物布置。
