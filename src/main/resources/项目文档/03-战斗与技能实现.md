# 战斗与技能实现

## 1. 核心类

| 类 | 职责 |
|---|---|
| `BattleService` | 校验关卡、加载双方、装配技能/装备/被动、调用引擎、结算进度与奖励 |
| `BattleEngine` | 行动值主循环、技能释放、伤害/治疗、事件、充能与被动调度 |
| `BattleRuntimeUnit` | 单个战斗单位的身份、位置、属性、技能、Buff、当前生命和行动进度 |
| `BattleUnitStats` | 战斗属性容器 |
| `BattleStatBoard` | 伤害、治疗、次数和技能统计 |
| `SkillV2OutputUnit` | V2 输出：属性、效果、追加 Buff |
| `SkillTargetResolver` | 根据目标枚举选择存活单位 |
| `FormulaEvalUnit` | 解析公式 JSON 并执行四则运算 |
| `DamageRatioUnit` | 防御和通用伤害倍率 |
| `ElementDamageUnit` | 元素加成与抗性 |
| `AtkSpeedCalcUnit` | 攻速与行动值换算 |

## 2. 战斗输入与输出

输入：当前玩家、关卡 ID；无尽塔还输入上一层己方剩余生命。

输出 `BattleResultVo` 包含：

- 胜负状态；
- 总行动值/时间信息；
- 战斗事件序列；
- 单位快照；
- 掉落与首通奖励；
- 主线/塔进度相关信息。

前端 `battle.html` 按事件播放动画，不重新计算胜负。

## 3. 单位初始化

### 玩家单位

来源：`PlayerLayout → PlayerRole`。每个单位加载：

- 角色实例属性；
- 玩家角色主动技能；
- 装备汇总三围；
- 武器普攻替换；
- 装备主动技能；
- 角色/装备被动；
- 网格位置与占地。

### 怪物单位

来源：`StageLevelMonster → Monster`。加载怪物属性、位置、普通攻击、小技能和大招。怪物和玩家共用同一引擎，没有独立策略 AI；选择哪个技能主要由充能状态和装载顺序决定。

## 4. 基础属性与最终面板

玩家单位的攻血防大体遵循：

```text
属性和 = 角色基础值 + 角色额外值 + 装备平坦值
最终属性 = 属性和 × (角色最终比例 + 装备战外最终比例) / 100
```

生命、防御与攻击同构。战外被动分为：

- 平坦加算：ATK、MAX_HP、DEF；
- 百分比加算：LIFE_STEAL、ATK_SPEED、FINAL_ATK/HP/DEF；
- 倍率叠乘：造成/受到、物理/元素伤害比例。

## 5. 攻速与行动值

换算：

```text
action = round(100 / attackSpeed)
attackSpeed = 100 / action
```

行动间隔至少为 1。攻速增减按倍率逐项作用，再反算行动值。

当前前端/描述工具采用约 `50 AV = 1 秒` 的展示口径，因此攻速 1、行动值 100 表现为约 2 秒一次行动。若设计目标是 `100 AV = 1 秒`，需要统一前端和描述文本，而不是只改引擎公式。

## 6. 战斗主循环

引擎不是双方轮流回合，而是统一行动值时间轴。每推进 1 AV，大致顺序：

```text
检查胜负
→ elapsedActionValue + 1
→ 所有主动技能结算本轴充能（普攻固定 +1）
→ 重复释放所有已充满技能（单轴 256 次保护）
→ 检查胜负
→ 清理到期临时属性/Buff
→ 处理脉冲 Buff
→ 检查胜负
→ 处理延迟/周期被动
→ 状态判定与事件充能
→ 再次释放本轴新达到满充的技能
→ 检查胜负
```

引擎存在最大 tick 和单次连发上限，防止无限循环。

## 7. 主动技能

### 类型

- `NORMAL`：普通攻击；
- `SMALL`：小技能；
- `ULTIMATE`：大招。

### 配置组成

```text
ActiveSkill
├── 所需充能模式/阈值
├── SkillCharge[] 充能条件
├── SkillOutput[] V2 输出
└── SkillEffect[] 旧效果（兼容）
```

### 所需充能

- `NORMAL`：引擎固定使用单位当前 `action` 作为最大充能；
- `SELF_BASE_ACTION`：使用自身基础行动值；
- `MANUAL`：后台填写固定阈值；
- `FORMULA`：公式计算阈值。

### 充能事件

- `CAST`：释放匹配技能；
- `RECEIVE`：受到匹配技能；
- `DEAL_DAMAGE`：匹配技能造成伤害；
- `TAKE_DAMAGE`：受到匹配技能伤害；
- `KILL`：匹配技能造成击杀；
- `ACTION_VALUE`：每经过指定行动值增加充能。

技能匹配支持任意技能、指定类型、流派、元素或具体技能。

### 释放选择

所有主动技能均有独立充能槽。普攻每 1 VA 固定获得 1 点基础充能，其他技能按自身配置充能；任意技能满充后立即释放，不等待单位行动回合。事件充能在当前 VA 达到满值时，也会在同一 VA 继续释放。玩家和怪物共用同一扫描机制。

## 8. V2 输出

`SkillOutputKind`：

- `ATTR`：修改攻、防、最大生命或高级战斗属性；
- `EFFECT`：造成伤害或治疗；
- `APPEND_BUFF`：挂载标准 Buff。

输出按 `sort` 升序执行。每条输出执行后可能改变后续输出的属性、生命、目标和统计，因此一个技能不是预先计算全部结果的快照。

`triggerRate` 对整条输出判定一次；多段/多目标共享这次判定结果。

## 9. 目标选择

目标类别包括：

- 自身；
- 己方/敌方首位、随机、当前生命最高/最低、最大生命最高/最低、生命比例最高/最低、攻击最高/最低；
- 己方/敌方全体、前排、后排；
- 全场同类条件与全体；
- 战斗事件专属目标：受击者、施法者、伤害来源、击杀者、被击杀者、特定目标。

通常仅在存活单位中选择。前排/后排依据阵营方向和 row 判断。

当前施法事件目标与 V2 输出实际目标可能分别解析；随机或动态目标存在不一致风险，详见问题文档。

## 10. 伤害公式

设技能公式结果为 `D0`：

```text
D1 = max(1, round(D0 × ATK / (ATK + DEF)))
```

当 `ATK + DEF <= 0` 时防御步骤直接返回原数值，这是一个特殊边界。

通用倍率：

```text
D2 = max(1, round(
  D1
  × DEAL_DMG_RATIO
  × TAKEN_DMG_RATIO
  × 类型造成倍率
  × 类型受到倍率
))
```

物理使用物理倍率，非物理使用元素倍率。

元素结算：

```text
最终伤害 = max(1, round(
  D2
  × (1 + (对应元素加成 + 全局元素加成) / 100)
  × max(0, 1 - 对应抗性 / 100)
))
```

元素包括：物理、中毒、点燃、冰冻、电击、灼烧。

## 11. 一段伤害的执行顺序

```text
计算当前段公式
→ 防御与伤害倍率
→ 元素与抗性
→ 尝试闪避
→ 扣生命
→ 写伤害统计
→ RECEIVE / DEAL_DAMAGE / TAKE_DAMAGE 充能
→ 判定死亡并记录事件
→ KILL 充能
→ 吸血
→ 主动伤害后被动
→ 脉冲伤害后被动
→ 击杀/被击杀被动
→ 扫描持续判定与阈值状态
```

多段技能每段重新读取当前属性。因此前一段触发的 Buff、被动或属性修改可以影响后一段。

## 12. 治疗与吸血

V2 治疗按公式计算，多段逐段执行，生命不超过最大生命。统计通常记录实际恢复量。

吸血按伤害结算值乘吸血比例，在伤害后、部分被动前执行。当前伤害统计和吸血可能使用理论伤害而非目标实际损失生命，过量伤害会放大吸血。

## 13. 被动技能

### 战外被动

- `OUT_BASIC`：攻血防平坦修改；
- `OUT_ADVANCED`：吸血、攻速、伤害倍率、最终属性比例。

在战斗单位构建阶段合并。

### V2 战斗被动

- `BATTLE_START`：立即、指定 AV 一次、每指定 AV；
- `BATTLE_JUDGE`：条件持续判定；
- `BATTLE_PULSE`：跨阈值脉冲，可一次跨越多个档位；
- `BATTLE_COMBAT`：伤害、施法、受击、击杀、闪避等事件。

战斗事件：造成/受到主动技能伤害后、释放/受到技能后、受到脉冲 Buff 伤害后、击杀、被击杀、闪避成功。

### 旧版被动

`IN_ANCHOR/IN_PERIODIC/IN_SUSTAINED` 仍保留兼容，但已标记废弃。旧锚点与 V2 输出的统计上下文并非完全兼容。

## 14. Buff

`BuffKind`：

- `ATTR`：持续属性修改；
- `PULSE`：周期伤害/治疗；
- `JUDGE_ATTR`：条件成立时维持属性；
- `JUDGE_BURST`：条件成立时触发一次效果；
- `DODGE`：按概率闪避匹配技能伤害。

叠加模式：不可叠加，或叠层并刷新时长。持续时间和脉冲间隔使用行动值。

注意当前循环先清理到期 Buff，再执行脉冲；若持续时长正好等于首次脉冲间隔，可能在触发前到期。

## 15. 公式引擎

公式保存为 JSON 节点/表达式，运行时读取单位属性、统计、技能次数或全局行动值。

数学能力仅包括：

```text
+  -  *  /  (  )
```

不支持 IF、MIN、MAX、比较、逻辑、幂和取模；比较由外围 `CompareOp` 完成。除零、非法公式或解析失败在多处会返回 0，而非抛错。

读取角色包括 SELF、GLOBAL、ALL_ALLY、ALL_ENEMY、EACH_TARGET 及事件锚点角色。ALL_ALLY/ALL_ENEMY 当前只聚合存活单位；角色死亡会让其历史累计值离开团队聚合。

## 16. 战斗统计口径

- `CAST`：技能真正释放次数，释放当次已计入；
- 造成/受到伤害次数：按每段 × 每目标；
- 主动伤害次数：按带主动技能标签的有效伤害段；
- `RECEIVE`：主要是收到主动技能伤害段，不等于所有技能作用；
- 闪避成功不产生伤害、吸血和相关伤害统计；
- 伤害量当前可能记录理论伤害（含过量）；
- 治疗量主要记录实际有效治疗，但旧治疗、吸血等来源未全部纳入同一统计口径。

## 17. 胜负与超时

任一阵营无存活单位即判负/胜；达到引擎最大推进限制仍未分胜负则按超时/平局逻辑返回。主线奖励只在胜利时结算；塔会按结果推进或标记死亡。
